# Ootique 친구 연결·투표 시나리오

업데이트: 2026-08-03

## 목표

친구와 함께하거나 혼자 오늘의 랜덤 컬러를 받고, 그 컬러에 맞는 OOTD를 올린다. 친구 모드에서는 같은 코드로 연결된 두 사람의 사진이 자동으로 만나야 한다. 공개 참가를 선택한 사진은 투표를 받고 순위에 반영된다.

## 핵심 사용자 시나리오

### 1. 혼자 참여

1. 사용자가 `혼자`를 선택한다.
2. 오늘의 컬러를 뽑는다.
3. 앱은 같은 날짜에는 같은 컬러를 보여준다.
4. 사용자는 그 컬러를 살린 옷을 입고 사진을 찍는다.
5. 사진을 저장하면 오늘의 공유 카드가 만들어진다.
6. 공개 참가를 선택한 경우에만 다른 사람의 투표 대상이 된다.

### 2. 친구와 참여

1. 사용자 A가 `친구와`를 선택하고 6자리 코드를 만든다. 코드는 자동 복사되어 메신저에 바로 붙여넣을 수 있다.
2. 사용자 B가 자기 기기에서 같은 코드를 입력한다.
3. 두 사람에게 같은 날짜·같은 컬러가 표시된다.
4. A와 B는 각자 자기 OOTD 사진 한 장을 업로드한다.
5. 한쪽만 올렸다면 상대 칸에는 `친구 사진을 기다리는 중`이 표시된다.
6. 상대가 올리면 새로 사진을 고르지 않아도 친구 사진이 자동 표시된다.
7. 두 사진이 모두 모이면 A/B 공유 카드 만들기 버튼이 활성화된다.
8. 한 사람이 사진을 교체하거나 삭제하면 상대 화면에도 같은 상태가 반영된다.

### 3. 투표와 순위

1. 사용자는 업로드할 때 `오늘의 투표에 공개`를 직접 선택한다. 기본값은 비공개다.
2. 공개 사진에는 신고·차단·삭제 기능이 항상 보인다.
3. 한 계정은 한 대결에 한 번만 투표할 수 있다.
4. 자신의 사진에는 투표할 수 없다.
5. 순위는 누적 인기보다 오늘의 컬러 참여 결과를 우선 보여준다.
6. 사진을 비공개로 바꾸거나 삭제하면 투표 화면과 순위에서도 제거된다.

## 반드시 지켜야 할 상태

- 친구 코드는 연결 열쇠일 뿐이며 사진 접근 권한을 무제한으로 주지 않는다.
- 같은 코드여도 오늘 참여한 두 사람의 사진만 서로 볼 수 있다.
- 사진 소유자는 언제든 공개 취소와 완전 삭제를 할 수 있다.
- 서버 조회 실패를 빈 사진으로 오해하지 않고 `연결 실패, 다시 시도`로 표시한다.
- 사진 업로드와 삭제는 중복 요청에도 결과가 한 번만 반영돼야 한다.
- 투표 수는 앱이 보낸 숫자를 믿지 않고 서버가 계산한다.

## 1차 통과 기준 — 친구 사진 자동 연결

- [x] 같은 날짜와 같은 6자리 코드는 두 기기에서 같은 컬러를 만든다.
- [x] 코드 생성 성공 뒤 클립보드에 자동 복사된다.
- [x] 입력칸은 6자리 전체를 표시하고 `코드 붙여넣기` 버튼으로 클립보드 값을 읽는다.
- [ ] A가 자기 사진을 올리면 B의 친구 사진 칸에 자동 표시된다.
- [ ] B가 자기 사진을 올리면 A의 친구 사진 칸에 자동 표시된다.
- [x] 상대 사진이 없을 때 수동 `친구 사진 선택`을 요구하지 않는다.
- [ ] 두 사진이 모두 있을 때만 A/B 공유 카드를 만들 수 있다.
- [ ] 사진 교체·삭제가 양쪽 기기에 반영된다.
- [ ] 다른 코드 사용자는 사진 URL을 알아도 열 수 없다.

## 2차 통과 기준 — 공개 투표와 순위

- [ ] 공개 동의한 사진만 투표 목록에 나타난다.
- [ ] 본인 투표와 중복 투표가 차단된다.
- [ ] 신고·차단·삭제가 실제 데이터와 화면에 반영된다.
- [ ] 비공개 전환 또는 삭제된 사진은 순위에서 빠진다.
- [ ] 조작된 앱 요청으로 투표 수를 직접 바꿀 수 없다.

## 현재 구현 검사 결과

실행: `npm run check`

- 통과: 무료 Supabase 서울 프로젝트, 비공개 Storage, DB·Edge Function 배포, SecureStore 토큰 보관, 6자리 코드 생성→참가→방장 승인, A→B·B→A 사진 조회, 사진 교체·삭제 서버 시나리오 자동 검사.
- 통과: 앱에서 수동 `친구 사진 선택`을 제거하고 5초마다 상대 사진 상태를 확인한다.
- 수정: Android 화면 캡처 변환에서 업로드가 시작되지 않던 경로를 제거하고, 사진 선택기가 만든 JPEG를 임시 파일로 저장해 업로드한다.
- 대기: 실제 두 기기에서 양방향 사진 자동 표시와 공유 카드 화면을 확인한다.
- 미구현: 공개 동의, 투표, 순위, 신고, 차단.
- 화면 반복처럼 보이는 긴 이미지는 우선 삼성의 `스크롤 캡처` 결과와 일반 화면을 비교한다. 일반 화면에서도 같은 카드가 반복될 때만 앱 렌더링 오류로 판정한다.

## 구현 전 승인할 것

이 단계부터 인증·DB·사진 저장·권한·개인정보가 추가되는 critical 작업이다.

1. 1차 범위를 친구 사진 자동 연결까지만 할지 확정한다.
2. 로그인 방식과 친구 코드의 만료·재사용 규칙을 정한다.
3. 사진 보관 기간, 완전 삭제 시간, 공개 기본값을 정한다.
4. DB와 파일 저장소 변경을 승인한다.
5. 투표·순위는 1차 실사용 확인 뒤 별도 승인한다.

## 승인 후 확정한 최소 보안 설계

- 백엔드: 별도 무료 Supabase 프로젝트의 Postgres, 비공개 Storage, Edge Function.
- 앱 연결: `@supabase/supabase-js` 없이 표준 `fetch`만 사용한다.
- 기기 비밀 보관: `expo-secure-store`에 회원 토큰을 저장한다.
- 6자리 코드는 10분 안에 만료되는 참가 요청용이다. 사진 접근 인증에는 쓰지 않는다.
- 방장이 참가 요청을 승인하면 방을 두 명으로 닫고, 두 기기에 서로 다른 임의 회원 토큰을 발급한다.
- 서버는 토큰 원문을 저장하지 않고 해시만 저장한다.
- 두 회원은 양쪽 사진을 읽을 수 있지만 자기 사진만 업로드·교체·삭제할 수 있다.
- Storage는 공개 URL을 만들지 않고 Edge Function이 인증된 요청에만 파일을 전달한다.
- 교체는 새 파일 검증 → DB 포인터 교체 → 이전 파일 삭제 순서로 처리한다.
- 삭제는 DB에서 먼저 읽기를 막고 파일 삭제를 재시도한다.
- 조회 실패와 `친구 사진 없음`을 구분하며 실패 시 화면의 기존 사진을 지우지 않는다.

### 구현에서 제외

- 공개 투표·순위·피드·신고
- 푸시 알림·백그라운드 동기화
- 계정 복구와 세 번째 참가자
- 코드만으로 즉시 사진 접근
- 공개 버킷과 장기 서명 URL
